# Deploy on Cloudflare (Workers with static assets)

The final site replaces the reference site (`housyspace-web-ref`, already on Cloudflare) at the same domain. The new site is fully static: Cloudflare serves `dist/` and `worker.js` only handles the host redirect and the preview `noindex`.

## Files

| File                 | Role                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `deploy.config.json` | The ONE constant: `productionOrigin`. Read by the site (`PRODUCTION_ORIGIN`: `site`, canonical, hreflang, sitemap, robots, JSON-LD, `_redirects` destinations), by `worker.js`, by `playwright.config.ts` and the e2e specs.                                                                                                                                                          |
| `wrangler.jsonc`     | Worker name, `assets.directory: ./dist`, `html_handling: drop-trailing-slash` (matches `trailingSlash: "never"`), `not_found_handling: 404-page` (serves `dist/404.html` with status 404), `run_worker_first` only for pages (not `/_astro`, `/brand`, `/media`, `/pdf`).                                                                                                             |
| `worker.js`          | (1) The other production host (www to apex or apex to www) answers 301 to the canonical origin, same path and query. If a `_redirects` rule already answers 301 (absolute destination) it is returned as is: one hop. (2) Any other host (`*.workers.dev`, branch previews) gets `X-Robots-Tag: noindex, nofollow`. A Vitest test (`worker.test.ts`) runs it against a fake `ASSETS`. |
| `dist/_redirects`    | Generated by `bun run build:production` only (never by the staging build). Real 301s for the site's retired URLs and for the whole URL space of the reference site, destinations absolute on the canonical origin.                                                                                                                                                                    |
| `dist/_headers`      | Generated with it: `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`. No CSP (depends on embeds and host; decide later).                                                                                                                                                                                                                          |

`.assetsignore` is not needed: the assets directory is `dist/`, which only holds the built site (the reference needed it because its assets directory was the repository root).

## Workers Builds settings

Connect the GitHub repository in Cloudflare (Workers & Pages, Create, Import a repository).

- Root directory: `/` (repository root, where `wrangler.jsonc` is).
- Build command: `bun run build:production` (builds with `ASTRO_PRODUCTION=1`, which sets site = the canonical origin and base = `/`, then prints the property sheet PDFs).
- Deploy command: `npx wrangler deploy` (default).
- Build variables: `CLIENT_ID`, `CLIENT_SECRET` (Mobilia; secrets), `NODE_VERSION=22`. Bun is preinstalled in the Workers Builds image; the PDF step needs Chromium: run `bunx playwright install chromium` first (put it in the build command: `bunx playwright install chromium && bun run build:production`) or the build fails at `build:sheets`.
- Branch builds: leave non-production branches on preview URLs (`*.workers.dev`); they get `X-Robots-Tag: noindex, nofollow` from the worker.
- Scheduled rebuild (listings freshness, AGENTS.md section 3.2): a Deploy Hook / cron trigger calling the build.

Optional job for a GitHub Actions production deploy (not active; `deploy.yml` keeps deploying staging to GitHub Pages):

```yaml
# deploy-production.yml (example, not enabled)
jobs:
  production:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: oven-sh/setup-bun@v2
      - run: bun install --frozen-lockfile
      - run: bunx playwright install chromium
      - run: bun run build:production
        env:
          { CLIENT_ID: "${{ secrets.CLIENT_ID }}", CLIENT_SECRET: "${{ secrets.CLIENT_SECRET }}" }
      - run: bunx wrangler deploy
        env: { CLOUDFLARE_API_TOKEN: "${{ secrets.CLOUDFLARE_API_TOKEN }}" }
```

## Canonical host: apex chosen

`https://housyspace.com` (apex, no www) is canonical. It is the origin the reference site and its sitemap already use and the one Google knows, so the migration changes no host: only the paths move (see below). The reference's worker already redirected `www` to the apex; `worker.js` keeps that.

To switch to `www` later change the single line in `deploy.config.json`. That moves `site`, every canonical/hreflang/Open Graph URL, the sitemap, robots, the worker redirect direction and every `_redirects` destination. It is a second migration for Google (every indexed URL changes host), so it needs: a 301 apex to www for the whole site (the worker does it from the same constant), the new origin verified in Search Console with a Change of Address, and DNS/custom domains for both hosts attached to the Worker. Do it only if there is a reason; the apex avoids it.

## Migration of the reference URLs

`src/shared/i18n/legacyRoutes.ts` (single source, built on the route map and the market slugs) lists every URL of the reference site (its 103 sitemap URLs, `/datos/`, the demo listings, its own `_redirects` retargeted). Each page has three rules (`/x`, `/x/`, `/x/index.html`), destination without trailing slash, 301. Tests prove every reference URL (fixture `referenceSitePaths.fixture.json`, generated once from the reference sitemap and folders) has a rule, every destination is a real route, and there are no loops or chains. `bun run check:seo` also checks that every destination of `dist/_redirects` is a page of the build.

Judgement calls to confirm with the client:

- `/propiedades/<demo-slug>/` (six demo listings, not real) all go to `/es/venta`.
- `/blog/es-fiable-valoracion-online/` goes to `/es/blog`: the new blog has no such article yet. Publish it (same slug would keep the URL) and change the rule to keep its ranking.
- `/servicios/asesoramiento` goes to `/es/servicios`, as the reference did.

Limits (Cloudflare): 2,000 static and 100 dynamic (splat) rules; the file has about 690 static and 5 splat. On Netlify the same file works, but a rule does not shadow an existing file unless forced (`!`), and Astro emits `dist/es/vender/index.html` and similar: add `force = true` redirects in `netlify.toml` if that host is ever used.

## Open decisions

- Worker name: `housyspace-web` is the reference's name. Deploying under the same name replaces the reference deployment and keeps its custom domains; a new name needs the domain moved to the new Worker. Decide at cut-over.
- DNS (ROADMAP I18): only the `@` and `www` records; never MX.
- Lead forms: see "Lead forms" below.
- `X-Robots-Tag` on the canonical host is never sent; pages carry `index` by omission and `noindex` meta where intended.

## Lead forms (not ported)

Today the new site has no endpoint: `LeadForm` (`features/leads/ui/leadForm.client.ts`) builds the message in the browser and opens WhatsApp or the mail client (`window.open`), then shows a "sent" text; the honeypot field `web` exists in the markup but nothing reads it, and nothing reaches the CRM or a mailbox (ROADMAP I3). The reference posts JSON to `/api/formulario` (`functions/api/formulario.js`): origin check, 60 KB limit, honeypot `web`, e-mail to digital@housyspace.com through Resend (`RESEND_API_KEY`, `MAIL_TO`, `MAIL_FROM`, `ALLOWED_ORIGINS`), 502 when the mail fails, a log line per confirmed submission. Missing to replace it: an endpoint, a shared Zod schema for the request, the island calling it instead of `window.open`, spam control (honeypot check plus Turnstile or rate limit), the Resend account and DNS records (SPF, DKIM), and privacy text naming the processor.

Option A, port the reference function into `worker.js` (`POST /api/formulario`): same behaviour and secrets, fastest and proven; cost: the Worker stops being a thin host layer and holds business code outside `src/` and the Zod schemas.
Option B, a separate Worker or Pages Function in `src/`-style TypeScript (own route, typed, shares the lead schema) sending through Resend or MailChannels: cleaner and testable, more work; MailChannels is an alternative to Resend (check its current Workers terms before relying on it); Resend is the proven default. Either way Mobilia stays read-only (AGENTS.md section 5) unless the owner decides to enable `POST /clientes` or `/solicitudes`.
